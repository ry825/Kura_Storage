# ファイル・フォルダの名前変更・移動 要求定義

## 1. 概要

KuraStorageの個人領域にある`ACTIVE`状態のファイルとフォルダについて、Androidアプリから名前変更および別フォルダへの移動を安全に実行できるようにする。

HDD上の実体とPostgreSQL上の索引を一貫して更新し、同名項目の上書き、個人領域外への移動、フォルダ階層の循環、不完全な操作結果の通常一覧への公開を防止する。

## 2. 背景

MVPではフォルダ作成、ファイル転送、ゴミ箱移動、復元までを実装したが、保存後のファイル名変更とフォルダ間移動はMVP後の機能として残している。そのため、利用者は誤った名前や保存先をAndroidアプリ内で修正できず、日常的なファイル整理を完結できない。

既存の`FileEntry`、`FileOperation`、`StorageGuard`、安全な相対パス解決、同一ファイルシステム内のrename、Trash・Restore復旧処理を拡張し、MVPで確立したデータ保護境界を維持したまま基本的な整理操作を追加する。

## 3. 実装対象の機能

### 3.1 ファイル・フォルダの名前変更

- 認証済み利用者が、自分の個人領域にある`ACTIVE`状態のファイルまたはフォルダの名前を変更できる。
- ファイルとフォルダには既存の`FileName`検証規則を適用する。
- 名前変更後も対象のFile ID、種別、所有者、ファイル内容、サイズ、MIME Type、内容を表す`fileVersion`を維持する。
- フォルダ名を変更した場合は、配下の全項目の相対パスを新しいパスへ整合させる。
- 同じ親フォルダに同名の`ACTIVE`項目が存在する場合は、既存項目を上書きせず競合として拒否する。
- 個人領域のルートフォルダ自体は名前変更できない。

### 3.2 ファイル・フォルダの移動

- 認証済み利用者が、自分の個人領域にある`ACTIVE`状態のファイルまたはフォルダを、自分の個人領域にある別の`ACTIVE`フォルダへ移動できる。
- 移動後も対象のFile ID、名前、種別、所有者、ファイル内容、サイズ、MIME Type、内容を表す`fileVersion`を維持する。
- フォルダを移動した場合は、配下の全項目の相対パスを移動先へ整合させる。
- 移動先に同名の`ACTIVE`項目が存在する場合は、既存項目を上書きせず競合として拒否する。
- フォルダを自分自身または自分の子孫へ移動できない。
- 個人領域のルートフォルダ自体は移動できない。
- User間の移動、Trash内からの移動、KuraStorage管理ルート外への移動を許可しない。

### 3.3 Server API・整合性・復旧

- 物理パスをClientから受け取らず、File ID、移動先Folder ID、検証対象の新しい名前だけで操作する。
- 各保護APIで認証、Device状態、所有者境界、対象状態、移動先状態を再検証する。
- HDD書き込み前に`StorageGuard`でMount、Storage ID、Filesystem、書き込み可否を検証する。
- HDD上の移動は同一ファイルシステム内のrenameを基本とし、操作開始前後の状態を`FileOperation`へ記録する。
- HDD操作とDB更新の途中でAPIが停止または失敗した場合、起動時および既存の限定Hosted Serviceで冪等に完了または元の状態へ収束させる。
- 自動判定できない状態は`RECOVERY_REQUIRED`として通常一覧へ公開せず、既存項目を上書きしない。
- 同一項目または関係するフォルダ階層への競合操作を直列化し、同時操作による循環、上書き、DB・HDD不整合を防止する。
- 名前変更・移動の結果を監査ログへ記録し、秘密情報、ファイル内容、物理絶対パスを記録しない。

### 3.4 Android操作

- 通常のファイル一覧または詳細から、対象ファイル・フォルダの名前変更操作を開始できる。
- 通常のファイル一覧または詳細から、対象ファイル・フォルダの移動操作を開始できる。
- 名前変更では現在名を確認できる入力UIを表示し、確定前にClient側でも基本的な入力検証を行う。
- 移動では個人領域内の移動可能なフォルダを選択でき、自分自身および子孫を移動先として確定できない。
- 操作前に対象と変更内容を確認でき、成功後は現在の一覧と詳細をServerから再取得する。
- 競合、対象消失、入力不正、認証切れ、Device失効、HDD利用不可、復旧要求を、利用者が次の操作を判断できる形で区別して表示する。
- 通信中断または失敗時に成功と表示せず、再取得によってServer上の確定状態を確認できる。

### 3.5 契約・文書・テスト

- OpenAPIへ名前変更・移動のRequest、Response、Error契約を追加し、ServerとAndroidで同じ契約を使用する。
- `docs/product-requirements.md`、`docs/functional-design.md`、`docs/architecture-design.md`、`docs/repository-structure.md`、`docs/development-guidelines.md`の該当箇所を実装内容へ整合させる。
- Domain・Application単体Test、API・DB・HDD結合Test、復旧Test、Android Repository・ViewModel・Compose UI Test、契約Testを追加する。
- Raspberry PiとAndroid実機で、ファイル・フォルダの名前変更・移動および主要な拒否条件を確認する。

## 4. 受け入れ条件

### 4.1 名前変更

- [x] 所有Userが`ACTIVE`状態のファイル名を変更できる。
- [x] 所有Userが`ACTIVE`状態のフォルダ名を変更できる。
- [x] フォルダ名変更後、配下の全項目を一覧・詳細・ダウンロードで利用できる。
- [x] 名前変更だけでは対象および配下ファイルの`fileVersion`が変化しない。
- [x] File ID、所有者、内容、サイズ、MIME Typeが名前変更前後で維持される。
- [x] 不正な名前、空文字、予約名、長さ超過を既存の名前検証規則に従って拒否する。
- [x] 同一親内の同名項目との競合を拒否し、既存項目を変更・削除しない。
- [x] 個人領域のルート、`TRASHED`項目、他Userの項目を名前変更できない。

### 4.2 移動

- [x] 所有Userが`ACTIVE`状態のファイルを別の`ACTIVE`フォルダへ移動できる。
- [x] 所有Userが`ACTIVE`状態のフォルダを別の`ACTIVE`フォルダへ移動できる。
- [x] フォルダ移動後、配下の全項目を一覧・詳細・ダウンロードで利用できる。
- [x] 移動だけでは対象および配下ファイルの`fileVersion`が変化しない。
- [x] File ID、名前、所有者、内容、サイズ、MIME Typeが移動前後で維持される。
- [x] 移動先の同名項目との競合を拒否し、既存項目を変更・削除しない。
- [x] フォルダを自分自身または子孫へ移動できない。
- [x] 個人領域のルート、`TRASHED`項目、他Userの項目を移動できない。
- [x] 他User領域、Trash領域、Storage Root外を移動先に指定できない。

### 4.3 整合性・障害時動作

- [x] 操作成功後、HDD上の実体とDBの名前、親ID、相対パスが一致する。
- [x] HDD操作失敗時にDBだけを成功状態へ更新しない。
- [x] HDD未Mount、Storage ID不一致、読み取り専用の場合は操作を開始しない。
- [x] HDD操作後かつDB確定前にAPIを停止しても、再起動後に同じ最終状態へ冪等に収束するか`RECOVERY_REQUIRED`となる。
- [x] 復旧中または安全に判定できない対象を通常一覧へ公開しない。
- [x] 同一項目および関係するフォルダへの並行操作で、上書き、循環、重複、DB・HDD不整合が発生しない。
- [x] 物理絶対パス、`..`、代替区切り文字、NUL、Symlinkを利用したStorage Root外操作を拒否する。

### 4.4 Android UI

- [x] ファイルとフォルダの名前変更を一覧または詳細から開始し、結果を確認できる。
- [x] ファイルとフォルダの移動を一覧または詳細から開始し、移動先を選択できる。
- [x] 移動先選択で、自分自身および子孫を不正な移動先として確定できない。
- [x] 成功後に一覧と詳細が再取得され、変更後の名前または場所が表示される。
- [x] 競合、入力不正、対象消失、認証・Device問題、Storage問題、復旧要求を区別して表示する。
- [x] 失敗または通信結果不明時に成功表示せず、再取得で確定状態を確認できる。

### 4.5 回帰・実機確認

- [x] 既存の一覧、詳細、フォルダ作成、Upload、Download、Trash、Restoreが引き続き成功する。
- [x] Server・Android・Security・設定検証の必須CIがすべて成功する。
- [x] Raspberry PiとAndroid実機で、ファイル名変更、フォルダ名変更、ファイル移動、配下を持つフォルダ移動を完了できる。
- [x] 実機で同名競合、循環移動、HDD利用不可の拒否を確認できる。

## 5. 成功指標

- File・Folderの名前変更および移動について、正常系、競合、循環、所有者境界、Storage異常、プロセス中断の自動Testがすべて成功する。
- Raspberry PiとAndroid実機で主要な名前変更・移動シナリオを連続10回実行し、HDDとDBの不整合、上書き、File IDまたは`fileVersion`の意図しない変更が0件である。
- 名前変更・移動後も対象ファイルの内容チェックサムが変化しない。
- 既存MVPの必須CIと実機Smoke Testに回帰がない。

## 6. スコープ外

以下はこの作業では実装しない。

- ファイルまたはフォルダのコピー、複製
- 複数項目の一括名前変更、一括移動、Drag & Drop
- User間または共有領域への移動
- 共有権限および共有項目に対する名前変更・移動
- Trash内の項目名変更、Trash内またはTrash外への任意移動
- 同名項目の上書き、内容置換、atomic replace
- ファイル内容の編集、過去Version保持、過去Versionへの復元
- ゴミ箱からの完全削除、30日保持、自動清掃
- Resumable Upload、Chunk Upload
- 検索、最近使用、お気に入り、タグ
- 外部変更監視、全件再Scan、`MISSING`判定
- サムネイル、派生データ、キャッシュ生成・無効化処理
- 自動バックアップ、Webアプリ、その他の後続機能

## 7. 制約・前提

- 現行MVPが実装済みで、`main`上の必須CIと実機E2Eが成功していることを開始前提とする。
- 現段階の認可は所有User境界とし、将来の共有機能追加時に編集権限へ拡張する。
- HDD上の実ファイルと物理階層を正とし、DBは索引および操作状態を保持する。
- 名前変更・移動は同じKuraStorage Storage Rootかつ同一ファイルシステム内に限定する。
- exFATの制約、Mount Option、固定UID・GID・Mask、`.storage-identity`検証を維持する。
- Clientへ物理絶対パスを公開せず、Client入力を物理パス解決へ直接使用しない。
- 独立Workerや新しいバックグラウンド実行基盤は追加せず、既存APIと限定Recovery Hosted Serviceの境界内で実装する。
- 新規ライブラリは、既存の.NET・Android標準機能で要求を満たせない場合に限って追加する。
