# 要求内容

## 概要

KuraStorageの個人ストレージを家族向けストレージへ拡張し、所有者がファイルまたはフォルダ単位で家族Userに権限を付与できるようにする。直接共有、フォルダからの継承、複数経路の最強権限解決をすべてのファイル操作に適用する。

## 背景

現在のKuraStorageはUserごとの個人ルートと所有者限定のファイル操作を前提としている。家族で写真や書類を共同利用するには、個人領域の分離を維持したまま、共有対象と操作ごとに許可範囲をサーバー側で一貫して判定する必要がある。また、共有対象の名前変更、移動、ゴミ箱移動、復元によって共有情報と実効権限が不整合にならない保証が必要である。

## 実装対象の機能

### 1. 共有データと家族User選択

- `Share`と`ShareMember`を永続化し、1つの共有対象に1つの共有設定、1つの共有ではUserごとに1つの権限という一意性を保証する。
- 認証User本人を除く`ACTIVE`な家族Userを、表示名順の共有候補として取得できる。
- クライアント指定の`ownerUserId`を信用せず、対象の所有者と認証Contextから共有の作成可否を決定する。

### 2. 共有の作成・参照・更新・解除

- ファイルまたはフォルダを複数の家族Userへ共有できる。
- 所有する共有と自分に直接共有された対象を、スコープと対象種別で取得できる。
- 所有者または対象に対する`MANAGER`が、メンバーの追加、権限変更、メンバー単位の解除、共有全体の解除を行える。
- 共有解除後は、他の有効な共有経路がないUserのアクセスが即時に失効する。

### 3. 4段階の共有権限

- `VIEWER < CONTRIBUTOR < EDITOR < MANAGER`の強度順を定義する。
- `VIEWER`は一覧、詳細、閲覧、ダウンロードを許可する。
- `CONTRIBUTOR`は`VIEWER`の操作に加え、共有フォルダ配下でのフォルダ作成とアップロードを許可する。ファイル共有には設定できない。
- `EDITOR`は`CONTRIBUTOR`相当の閲覧・作成操作に加え、権限範囲内の名前変更、移動、内容編集、ゴミ箱移動を許可する。
- `MANAGER`は`EDITOR`の操作に加え、共有メンバーと権限の管理を許可する。
- `ADMIN` Roleに他Userのファイルへの暗黙権限を付与しない。

### 4. 直接共有・継承・複数経路の権限解決

- ファイルの直接共有は対象ファイルにだけ適用し、親、兄弟、その他の項目へ権限を波及させない。
- フォルダの共有は対象フォルダ自身とすべての子孫項目へ継承する。
- 対象への直接共有とすべての祖先フォルダ共有を評価し、同一Userに複数経路がある場合は最も強い権限を実効権限とする。
- 直接共有で継承権限を弱める拒否・例外設定は設けない。
- 保護対象のファイルAPIは要求ごとに所有者、直接共有、継承共有を再評価し、必要権限未満の操作を拒否する。

### 5. 共有対象の変更と整合性

- 共有対象の名前変更ではFile IDと共有の関連を維持し、共有一覧と詳細に変更後の名前を反映する。
- 共有対象または配下項目の移動後は、保持された直接共有と新しい祖先経路から実効権限を再評価する。
- `EDITOR`による移動は、移動対象だけでなく移動元と移動先に必要な権限を持つ場合だけ実行でき、移動による権限境界の迂回を許可しない。
- 共有対象がゴミ箱へ移動された間は通常の共有一覧、閲覧、変更の対象から除外し、復元後は保持された直接共有と復元先の祖先経路から実効権限を再評価する。
- 完全削除時は対象と子孫の共有管理情報を同一の管理処理で削除し、孤立した共有を残さない。

### 6. Server APIと応答契約

- `GET /api/v1/shares/candidates`で共有候補を取得できる。
- `POST /api/v1/shares`で共有を作成でき、ファイル共有への`CONTRIBUTOR`指定は`400 INVALID_SHARE_PERMISSION`で拒否する。
- `GET /api/v1/shares?scope=owned|received&targetType=FILE|FOLDER`で共有一覧を取得でき、フォルダ共有の子孫をルートと重複して個別展開しない。
- `GET /api/v1/shares/{shareId}`、`PUT /api/v1/shares/{shareId}/members/{userId}`、`DELETE /api/v1/shares/{shareId}/members/{userId}`、`DELETE /api/v1/shares/{shareId}`を提供する。
- ファイル一覧と詳細は所有者情報、実効権限、`OWNER | DIRECT | INHERITED`の権限元、必要な場合の共有元対象IDを返す。
- 認可失敗や非公開対象の応答によって、他Userの項目や物理パスの存在を漏らさない。

### 7. Androidの共有UI

- 共有画面で、自分に直接共有されたファイルとフォルダ共有のルートを、種別、所有者、自分の権限とともに表示する。
- 所有者または`MANAGER`が、詳細画面から共有相手の追加、権限変更、相手単位の解除、共有全体の解除を実行できる。
- フォルダ共有には配下への継承を、ファイル共有には対象限定を表示し、ファイル共有の権限選択肢から`CONTRIBUTOR`を除外する。
- 継承権限で開いた配下項目に、共有元フォルダと自分の実効権限を表示する。
- 各操作を権限に応じて表示または無効化し、Serverが返す最新の認可結果を正とする。

## 受け入れ条件

### 共有データと管理API

- [ ] Migrationにより`shares`と`share_members`を作成・前方適用でき、対象とメンバーの一意制約、列挙値制約、参照整合性をDBとApplicationの両方で保証できる。
- [ ] 認証User本人と非`ACTIVE` Userを除外した共有候補を表示名順で取得できる。
- [ ] ファイルとフォルダの共有作成、所有・受信一覧、詳細取得、メンバー追加・権限変更・解除、共有全体の解除がAPI契約どおり動作する。
- [ ] ファイル共有への`CONTRIBUTOR`、本人または非`ACTIVE` Userの指定、重複メンバー、無権限の共有管理を安定したError Codeで拒否できる。
- [ ] 所有者と`MANAGER`だけが共有を管理でき、解除後のアクセス失効が次のAPI要求で反映される。

### 認可とファイル操作

- [ ] 所有者、直接共有、すべての祖先フォルダ共有を解決し、複数経路の最強権限とその権限元を返せる。
- [ ] `VIEWER`、`CONTRIBUTOR`、`EDITOR`、`MANAGER`ごとに、一覧・詳細・ダウンロード、作成・アップロード、名前変更・移動・編集・削除、共有管理の許可と拒否が仕様どおり分かれる。
- [ ] ファイル直接共有が他項目へ波及せず、フォルダ共有が子孫全体へ継承される。
- [ ] 弱い直接共有が強い継承共有を上書きせず、最強権限を維持する。
- [ ] `ADMIN`を含む非所有Userは、有効な直接共有または継承共有がない他Userの項目をファイルAPIから利用できない。
- [ ] 認可Domain/Applicationの所有者、直接共有、継承、最強権限、操作別境界値を含むユニットテストが、認証・認可のカバレッジ95%以上を満たす。

### 変更・削除・復元の共有整合性

- [ ] 共有対象を名前変更しても共有とFile IDが維持され、最新の名前が共有一覧と詳細に表示される。
- [ ] 移動前後で直接共有を維持しつつ祖先フォルダ共有を現在の経路から再評価し、移動元・移動先の権限不足ではHDD変更前に拒否する。
- [ ] ゴミ箱移動中の共有対象は受信一覧と通常操作から除外され、復元後は直接共有と復元先の継承経路が再評価される。
- [ ] 完全削除後に対象と子孫の`Share`、`ShareMember`が残らず、共有解決や共有一覧から参照されない。
- [ ] 名前変更、移動、ゴミ箱移動、復元、完全削除について、所有者、各共有権限、直接・継承・複数経路を組み合わせた統合テストが成功する。

### Android UIとE2E

- [ ] Androidで共有一覧、共有候補選択、権限選択、メンバー更新・解除、共有全体の解除を実行できる。
- [ ] 対象種別に応じた継承範囲、所有者、実効権限、継承時の共有元フォルダを画面で確認できる。
- [ ] ファイル共有で`CONTRIBUTOR`を選択できず、各権限に不足するファイル操作と共有管理をUIから実行できない。
- [ ] 所有者と共有先Userを使うServer API E2EおよびAndroid実機E2Eで、共有作成から閲覧・変更・解除までの許可・拒否が確認できる。
- [ ] LAN経由とZeroTier経由のどちらでも同じHTTPS Hostnameと共有・認可契約が機能する。

## 成功指標

- 所有者と共有先Userの操作が4段階の権限表どおりに分かれ、不足権限での成功が0件である。
- 直接共有、継承共有、複数経路、共有解除、移動、ゴミ箱移動、復元、完全削除の境界を自動テストで再現できる。
- Domain/Application全体のユニットテストカバレッジ80%以上、認証・認可のカバレッジ95%以上を維持する。
- Raspberry Pi環境とAndroid実機で、家族User間の共有作成、利用、権限変更、解除の主要フローが成功する。

## スコープ外

以下はこのフェーズでは実装しない。

- 個別ファイルへの拒否ACL、継承停止、または継承権限を弱める例外設定
- 家族外User、グループ、公開URL、パスワード付きLink、有効期限付き共有
- 共有機能とは独立した検索、最近使用、自動バックアップ、メディア派生データ機能
- User作成、User無効化、Role変更などのUser管理UIまたは共有候補API経由の管理操作
- Webクライアントと外部クラウドストレージへの共有
