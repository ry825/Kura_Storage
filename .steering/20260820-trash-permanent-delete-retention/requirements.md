# ゴミ箱の完全削除・30日保持・自動清掃 要求仕様

## 概要

ゴミ箱内のFile・Folderを利用者が明示的に完全削除できるようにし、ゴミ箱へ移動してから30日を経過した項目をServerが自動的に完全削除する。完全削除ではHDD上の実体と関連管理情報を整合して削除し、独立した監査ログと管理者向け容量警告により長期運用を可能にする。

## 背景

現行実装は`ACTIVE`項目のゴミ箱移動と`TRASHED`項目の復元だけを提供しており、ゴミ箱内のデータが無期限に残る。長期運用ではHDD容量を継続的に消費し、不要データを安全に解放できない。

完全削除はHDDとPostgreSQLをまたぐ不可逆操作であるため、物理削除だけ、または管理情報削除だけが完了した不整合を放置してはならない。また、保持期間を容量都合で短縮せず、容量不足は管理者へ警告し、完全削除の事実は通常のファイル索引と分離した監査ログへ必要最小限だけ残す必要がある。

## 実装対象の機能

### 1. 利用者による完全削除

- 認証済み利用者が、自分のゴミ箱にあるFileまたはFolderを選択して完全削除できる。
- 完全削除前に、元へ戻せない不可逆操作であることをAndroidの確認画面で明示する。
- `ACTIVE`項目、個人領域Root、他Userの項目、存在しない項目は完全削除できない。
- Folderの完全削除では、配下の実体と管理情報を同じ操作対象として再帰的に削除する。
- 二重送信、通信結果不明、並行Restore・完全削除・自動清掃が発生しても、同じ最終状態へ安全に収束する。

### 2. 30日保持と自動清掃

- ゴミ箱へ移動した日時`trashedAt`をUTC基準の保持開始時刻とする。
- `trashedAt`から30日を経過したゴミ箱項目を、Serverの定期Workerが自動完全削除する。
- 初期実装では日次実行とし、起動後にも期限超過項目を処理できる。
- Workerは対象を一定件数ずつ取得し、複数インスタンスまたは手動完全削除との重複実行を防ぐ。
- HDD容量不足を理由に、30日未満の項目を自動完全削除しない。
- 自動清掃の失敗は記録し、次回実行または操作ジャーナル復旧で再試行できる。

### 3. 整合した物理・管理情報削除と復旧

- 完全削除用の`FileOperation`を作成し、物理削除、`FILESYSTEM_DONE`、DB内関連情報削除、`FileEntry`削除、`COMPLETED`の順序を管理する。
- 物理削除後にDB処理が失敗した場合、実体が存在しないことを正常な削除済み状態として扱い、再実行でDB削除を完了する。
- 判断不能または安全に自動復旧できない場合は`RECOVERY_REQUIRED`として通常操作から隔離し、成功として表示しない。
- 完全削除後は`FileEntry`を`DELETED`等の論理削除状態で残さない。
- 対象に紐づく共有、同期、最近使用、Backup Receipt、Thumbnail、低・中画質派生データ等、実装時点で存在する関連管理情報と物理派生データを削除する。
- 未実装機能の空テーブルや仮実装は追加しない。将来追加される関連情報が完全削除処理へ明示的に参加できる削除境界を定義し、既存の外部キー制約とApplication処理を検証する。
- 完了済み操作ジャーナルは復旧に不要となる期間まで保持できるものとし、完全削除対象の`FileEntry`に依存して孤児化しない。

### 4. 完全削除の監査ログ

- 手動完全削除と自動完全削除について、成功、拒否、復旧要求を追記専用の監査ログへ記録する。
- 成功監査は関連管理情報と`FileEntry`を削除するDBトランザクション内で保存し、監査保存失敗時はDB削除をRollbackして再試行可能にする。
- 監査ログは完全削除対象の業務データと独立して保持し、`FileEntry`や共有状態の代替として使用しない。
- 監査ログにはAction、結果、削除元種別、削除対象ID、実行主体種別、Actor User・DeviceまたはWorker、Request ID、実行日時など必要最小限だけを保存する。
- ファイル名、元の相対Path、物理絶対Path、ファイル内容、認証情報、秘密情報は保存しない。

### 5. 容量警告と管理状態

- Storage全体容量、利用可能容量、警告判定、保持期限内のゴミ箱概算容量、期限超過件数、直近自動清掃結果を認証済みAdminだけが取得できる。
- 警告閾値は設定可能とし、既存の`MinimumFreeBytes`による書込安全余裕と矛盾しない既定値を正式文書で定義する。
- 容量が警告閾値以下でも30日保持を短縮せず、Adminへ空き容量不足と対応方法を表示する。
- 匿名`GET /api/v1/system/health`へ空き容量、物理Path、Storage ID、DB詳細を追加しない。
- Memberまたは未認証利用者は詳細容量・Worker状態を取得できない。
- 容量警告の表示失敗は完全削除の安全性確認や保持期限判定を迂回させない。

## 受け入れ条件

### 利用者による完全削除

- [x] 認証済み利用者が自分の`TRASHED` Fileを確認後に完全削除できる。
- [x] 認証済み利用者が自分の`TRASHED` Folderとその配下を確認後に完全削除できる。
- [x] 完全削除後、対象実体、ゴミ箱用Container、対象と配下の`FileEntry`、実装済みの関連管理情報・派生データが残らない。
- [x] 完全削除後の通常一覧、ゴミ箱一覧、詳細、Download、Restoreから対象へ到達できない。
- [x] `DELETED`状態または完全削除済みFileの索引行を追加しない。
- [x] `ACTIVE`、Root、他User、存在しない対象を、所有関係を漏えいしないErrorで拒否する。
- [x] Androidは不可逆性を明示した確認操作を必要とし、処理中の重複送信を防ぐ。
- [x] Androidは成功後にServerからゴミ箱一覧を再取得し、通信結果不明時は成功を推測しない。

### 30日保持と自動清掃

- [x] `trashedAt`から30日未満の項目は自動完全削除されない。
- [x] `trashedAt`からちょうど30日以上の項目は自動清掃対象になる。
- [x] 日次Workerおよび起動後の実行で、期限超過項目をBatch単位に完全削除できる。
- [x] 手動完全削除、Restore、複数Workerが競合しても二重削除やDB・HDD不整合を起こさない。
- [x] HDD空き容量が警告閾値以下でも、30日未満の項目を削除しない。
- [x] Storage未Mount、読取専用、DB障害、Process停止後に、安全に再試行、復旧、または`RECOVERY_REQUIRED`へ移行する。

### 関連管理情報と監査ログ

- [x] 実装済みの共有、同期、最近使用、Backup Receipt、派生データ等が存在する場合、対象と配下の関連情報を完全削除する。
- [x] 現時点で未実装の関連機能について、空の業務テーブルを先行追加しない。
- [x] 手動・自動の完全削除成功後も、独立した監査ログだけは対象IDと必要最小限の情報を保持する。
- [x] 監査保存失敗時はDB上の関連情報と`FileEntry`削除をCommitしない。
- [x] 監査ログ、Application Log、API Responseにファイル名、相対・絶対Path、内容、Token、秘密情報を出力しない。

### 容量警告と管理状態

- [x] Adminは詳細Storage状態、ゴミ箱概算容量、期限超過件数、直近自動清掃結果を確認できる。
- [x] 容量が設定済み警告閾値以下の場合、AndroidのAdmin向け表示で警告と対応案内を確認できる。
- [x] Member、未認証利用者、匿名Healthは詳細容量とWorker状態を取得できない。
- [x] 警告閾値、保持日数、実行間隔、Batch Sizeを設定で検証し、不正値ではServerを起動しない。

### 回帰・運用

- [x] 既存の一覧、詳細、Folder作成、Upload、Range Download、Trash、Restore、Rename、Moveが引き続き成功する。
- [x] 既存のStorage Root、`storageId`、Mount、Symbolic Link、相対Pathの安全境界を維持する。
- [x] Raspberry Pi、PostgreSQL、共有exFAT HDD、Android実機で手動完全削除、自動清掃、容量警告、障害復旧を確認できる。
- [x] Server・Androidの必須CI、Migration適用・Rollback確認、Security検査、実機E2Eが成功する。
- [x] 正式文書、OpenAPI、設定例、運用手順と実装が一致する。

## 成功指標

- 30日未満の自動完全削除: 0件。
- 期限超過項目の次回正常Worker完了後の未処理件数: 0件。
- 正常完了または復旧完了後の、対象実体・`FileEntry`・実装済み関連管理情報の残存: 0件。
- 手動・自動完全削除の監査記録欠落: 0件。
- 完全削除・自動清掃によるDB・HDD不整合、他User削除、Storage Root外削除: 0件。
- 容量警告時の保持期間自動短縮: 0件。

## スコープ外

以下はこの作業では実装しない。

- 完全削除後の復元、Undo、第二媒体またはBackupからの復元。
- HDD容量不足を理由とする30日未満の自動削除。
- ゴミ箱保持期間を利用者ごとに変更する機能。
- ゴミ箱の複数選択、一括完全削除、「ゴミ箱を空にする」操作。
- 未実装の共有、同期、最近使用、Backup、Media、Thumbnail、派生データ機能そのもの。
- 監査ログ保持期間、アーカイブ、監査ログ削除Worker。
- 一般利用者向けのHDD総容量・空き容量詳細表示。
- Public Internetへ公開する管理画面またはMetrics Endpoint。
